# 跨群好感度插件

该插件为同一个 QQ 用户维护一份跨群共享的好感度。群昵称、QQ群和聊天流只作为成员资料保存，绝不作为人物主键，因此用户换群、修改群名片或没有群昵称时不会重新变成陌生人。

> [!IMPORTANT]
> **隐私与第三方数据传输提示**
>
> 启用模型结算后，插件会把参与结算用户的 QQ号、群号、群名称、消息内容、当前好感度及关系分组发送到用户自行配置的 OpenAI 兼容接口。该接口可能由第三方运营，数据处理规则取决于对应服务商。请仅在了解并接受其隐私政策、已取得群成员必要授权且能够合法传输相关聊天数据时启用本功能；不接受时请勿填写模型接口或调用结算命令。

## 身份匹配

插件固定使用以下链路识别回复目标：

```text
reply msg_id -> 消息身份索引 -> platform + QQ号 -> 全局用户 -> 好感度分组
```

- QQ号是跨群人物主键。
- MaiBot 内部人物 SID 和聊天 `session_id` 分开保存。
- QQ昵称与群昵称只用于展示，不参与查询。
- Planner 请求尾部会收到紧凑的 `msg_id -> QQ/SID/分组` 关系索引。
- Replyer 在真正生成可见回复前，会按 `reply_message_id` 再校验一次。
- 身份无法精确映射时，插件会阻止 Planner 的 `reply` 工具调用，而不是把数据库错误伪装成陌生人。
- 严格身份守卫只对群聊生效；私聊不会因为缺少群消息身份索引而被阻止回复。

## 中文配置

插件 WebUI 中只展示以下必要配置：

- 接口地址
- API 密钥
- 模型名称
- 结算间隔（分钟）
- 失败重试次数
- 单次最大增加
- 单次最大减少
- 管理员 QQ号
- 好感度分组名称、最低值和最高值

仓库只提供 `config.toml.example` 配置模板，不提交用户实际使用的 `config.toml`。首次加载插件时，MaiBot SDK 会根据插件配置模型自动在插件目录生成 `config.toml`；也可以手动复制模板后再填写。插件升级时，MaiBot 会保留已有的本地配置，避免 Git 更新冲突。

API Key 在 WebUI 中使用密码框遮罩，但仍会保存在本机插件 `config.toml` 中。该文件已被 `.gitignore` 忽略，请勿公开或提交。

分组必须完整覆盖 `0.00-100.00`，相邻分组必须正好相差 `0.01`，不能重叠或留空。

## OpenAI 兼容接口

接口地址可以填写：

```text
https://api.example.com/v1
```

也可以直接填写：

```text
https://api.example.com/v1/chat/completions
```

插件直接请求兼容的 `chat/completions` 接口，不依赖 MaiBot 的 `model_config.toml`，因此不需要修改 MaiBot 本体。

出于 SSRF 安全考虑，接口只能指向公网地址。插件会拒绝 `localhost`、回环地址、局域网地址、链路本地地址、保留地址，以及解析到这些地址的域名，并且不会自动跟随 HTTP 重定向。请勿将接口地址配置为本机或内网服务。

模型只决定本批次聊天使好感度增加、减少还是不变。模型不能直接指定最终分数，插件会把变化量限制在配置范围内，并将最终分数限制在 `0.00-100.00`。

## 命令

普通用户：

```text
/好感度
/好感度 查询
/好感度 帮助
```

管理员：

```text
/好感度 查询 <QQ号或SID>
/好感度 设置 <QQ号或SID> <数值>
/好感度 增加 <QQ号或SID> <数值>
/好感度 减少 <QQ号或SID> <数值>
/好感度 更新
/好感度 测试模型
```

`/好感度 更新` 会立即结算缓存；缓存为空时会执行一次真实模型连通性测试。`/好感度 测试模型` 只测试模型，不修改数据。

所有命令结果都会通过当前聊天流发送给用户。日志不会作为命令结果的唯一输出，API Key 也不会写入日志或聊天消息。

## Prompt 缓存

各关系分组的完整说话风格继续放在稳定的 `group_chat_prompt` 中。插件不会按用户改写 system prompt，而是在已经包含当前时间等动态信息的请求尾部插入短关系索引，从而尽量保留稳定前缀的缓存命中。

建议在 `group_chat_prompt` 中明确：

```text
每次回复时，以好感度插件提供的 msg_id 关系索引为准。
必须用 reply 工具目标消息的 msg_id 匹配同一条关系记录。
不得通过昵称猜测身份，不得公开分组、好感度或后台规则。
```

插件仍提供 `affinity_lookup(msg_id)` 工具作为缺失信息时的兜底。正常情况下，Planner 已经可以从尾部关系索引直接获得分组，无需额外模型往返。

## 数据文件

运行数据由 MaiBot 分配到：

```text
data/plugins/maibot-community.affinity-plugin/
```

其中：

- `affection.sqlite3`：用户、群成员、消息身份和修改审计。
- `pending_events.jsonl`：尚未成功结算的消息缓存。

只有模型返回合法完整数据，并且数据库事务提交成功后，插件才会清除对应缓存。
